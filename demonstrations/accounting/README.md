# tnreason for rule-based accounting

We here demonstrate the usage of `tnreason` for rule-based accounting in a simple example.

## Background

The generation of accounting proposals given receipts of a business process is a particular example of a inference problem. 
Representing the model based on logic enables a human understandable, maintainable and extensible model.

## Toy Example

We here demonstrate the generation and maintainance of a hybrid model containing hard rules and probabilistic rules.
In this example, we have a set of receipty, which are of exactly one of the product classes 
  - PRODUCT_CLASS_SEA-CP_01
  - PRODUCT_CLASS_SEA-CP_02
  - PRODUCT_CLASS_SEA-CP_03
  - PRODUCT_CLASS_SEA-CP_04
  - PRODUCT_CLASS_SEA-CP_05
To each receipt an accounting proposal has to be generated by an assignment of an account from
  - ACCOUNT_Account_3300
  - ACCOUNT_Account_3400
  - ACCOUNT_Account_4605
and a tax rate
  - TAX_RATE_19
  - TAX_RATE_7
